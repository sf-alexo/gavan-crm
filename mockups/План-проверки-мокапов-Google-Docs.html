План проверки мокапов CRM «Чистая Гавань»

Проверка глазами бизнес-пользователя (менеджер, диспетчер, руководитель).
Основание: backlog разработки (Epic → Feature → User Story → Acceptance Criteria).
Порядок: Сотрудники → Клиенты → Объекты → Лиды → Договора → Заказы.

Как пользоваться. Открыть соответствующий мокап и по каждой User Story отметить: да / нет / неясно / нет в мокапе. Формат заметки: US-0XX | экран | результат | комментарий одним предложением

1. Сотрудники

Мокап: employees.html
Бэклог: E08-F01 (US-048–050), частично E08-F02, E01-F02

ID Что проверить как бизнес-пользователь Результат
US-048 Могу завести нового сотрудника с понятными полями?
US-049 Видно роль человека (менеджер, клинер, бригадир и т.д.)?
US-050 Понятно, кто активен, а кого уже нельзя ставить на работу?
US-051–053 Видно ли бригады / понятно ли, кого назначать на заказ вместе? (если есть в мокапе)
US-004–005 Чувствуется ли различие ролей и доступа, или экран «для всех одинаковый»?

Сценарий дня: «Нужен состав на завтра — вижу, кого можно поставить.»

2. Клиенты

Мокап: clients.html
Бэклог: E03-F01 (US-016–019), E13 (US-076)

ID Что проверить как бизнес-пользователь Результат
US-016 Могу создать клиента с первого обращения?
US-017 Карточка отвечает на вопрос «кто этот клиент?» без звонка коллегам
US-018 / US-076 В карточке видна история: что было, кто трогал, чем закончилось
US-019 Есть ли намёк на защиту от дублей (поиск до создания, предупреждение)?
AC связей Из клиента видно заявки / договора / заказы?

Сценарий дня: «Клиент перезвонил — за 30 секунд понял контекст.»

3. Объекты

Мокап: objects.html (при необходимости — scan.html)
Бэклог: E06-F01 (US-036–037), E06-F02 (US-038–041)

ID Что проверить как бизнес-пользователь Результат
US-036 Могу завести объект клиента (адрес, тип, площадь)?
US-037 У объекта есть уникальный ID / понятный идентификатор для поля?
AC Один объект может иметь историю нескольких заказов?
US-038–041 QR: сотрудник сканирует → система узнаёт объект → пускает только при активном заказе и праве?

Сценарий дня: «Бригада едет на адрес — объект однозначен, история заказов на месте видна.»

4. Лиды (заявки)

Мокап: leads.html
Бэклог: E03-F02 (US-020–024), связка с сайтом E02-F02

ID Что проверить как бизнес-пользователь Результат
US-020 Вижу входящие заявки и не теряю новые
US-021 Открыл заявку — понятны клиент, услуга, источник, суть запроса
US-022 Могу назначить ответственного менеджера
US-023 Могу менять статус / стадию по понятной воронке
US-024 Есть явный путь «заявка → договор / сделка»
AC истории Смена статуса и назначения остаются в истории
US-013 (связка) Понятно, что заявка могла прийти с сайта

Сценарий дня: «5 заявок с утра — у каждой есть хозяин и следующий шаг.»

5. Договора (сделки)

Мокап: deals.html
Бэклог: E04-F01 / F02 (US-025–030), E13 (US-077)

ID Что проверить как бизнес-пользователь Результат
US-025 Договор рождается из заявки, связь не рвётся
US-026 / US-029–030 Воронка по стадиям читается; перевод стадии понятен
US-027 Виден ответственный
US-028 Рядом клиент, заявка, объекты — без «прыжков по таблицам»
US-077 История стадии и действий сохраняется
AC Недопустимый скачок стадии, если есть, блокируется понятно

Сценарий дня: «Заявка квалифицирована → договор в воронке → видно, на ком мяч.»

6. Заказы

Мокапы: orders.html, order-assign.html, order-work.html, order-quality.html
Бэклог: E05 (US-031–035), E07 (US-042–047), E08-F02 (US-053), E13 (US-078)

6.1. Создание и планирование (E05)

ID Что проверить как бизнес-пользователь Результат
US-031 Заказ из договора содержит: клиент, договор, объект, услуга, дата, ответственный, исполнитель/бригада, статус
US-032 Дату / слот можно назначить
US-033 / US-034 / US-053 Назначается исполнитель или бригада
US-035 Заказ виден в календаре

6.2. Выполнение (E07)

ID Что проверить как бизнес-пользователь Результат
US-042 Исполнитель может стартовать работу (после QR / допуска)
US-043–045 Этапы видны, закрываются по порядку, результат фиксируется
US-046 Можно прикрепить фото / видео к этапу
US-047 Завершение только когда обязательное сделано; время и статус сохраняются
US-078 История заказа читаема руководителю

Сценарий дня: «Согласованный договор → заказ в календаре с людьми → выезд → этапы → фото → закрытие.»

7. Сквозной прогон (E16-F02)

Прогнать по мокапам цепочку бэклога:

Заявка → Клиент → Договор → Заказ → Исполнитель → QR → Выполнение → Результат → История

На каждом звене отметить:

  1. Связь с предыдущим шагом видна?
  2. Понятно, кто следующий ответственный?
  3. История не обрывается?

8. Что сознательно не требовать от этих 6 экранов

По бэклогу это другие эпики или Future для текущего просмотра:

  • сайт и калькулятор (E-02);
  • онлайн-оплата (E-10);
  • клиентский кабинет (E-11);
  • Telegram / SMS (E-09);
  • лояльность (E-14);
  • аналитика по филиалу / региону / городу (E-12) — только если явно есть в мокапе.
