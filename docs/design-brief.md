ТЗ дизайнеру: UI/UX CRM «Чистая Гавань»


1. О продукте

Внутренняя CRM/операционная система клининговой компании. Пользователи — сотрудники офиса (менеджер/оператор) и клинеры на объектах.

Макеты-референсы (структура экранов и сценарии, не финальный визуал):
• Локально: папка mockups/
• Онлайн: https://gavan-phi.vercel.app/

Задача: на основе макетов сделать цельный UI (Figma), пригодный для передачи в разработку (React). Бизнес-логику и набор экранов не расширять.

Палитра, типографика и детали визуального стиля — на выбор дизайнера. Ограничение: интерфейс должен выглядеть как рабочий B2B-инструмент (читаемые таблицы, понятные статусы), а не как маркетинговый лендинг.


2. Две поверхности

CRM (менеджер)
• Кто: менеджер / оператор
• Устройства: desktop-first, адаптив до планшета
• Тон: плотный UI — таблицы, kanban, календарь

Клинер
• Кто: сотрудник на объекте
• Устройства: только телефон
• Тон: максимально просто, крупные зоны нажатия

У клинера — отдельный упрощённый интерфейс (без полного сайдбара CRM). Должен удобно работать одной рукой и в перчатках: крупные кнопки (от 44–48 px), мало мелкого текста, минимум вложенных жестов, основная кнопка действия на всю ширину.


3. Экраны в scope

Покрыть только перечисленные ниже. Остальные страницы макетов (QA, кабинет клиента, задачи, история и т.д.) — вне этого ТЗ.


3.1. Вход

Вход в CRM
Референс: https://gavan-phi.vercel.app/

• Форма: email, пароль, вход.
• В макете есть разделение «Я менеджер» / «Я сотрудник» — в дизайне сохранить идею разных сценариев после входа (desktop CRM vs мобильный клинер), конкретную реализацию UI — на усмотрение.
• Адаптив: desktop и mobile.


3.2. Менеджер (CRM)

Дашборд
Референс: https://gavan-phi.vercel.app/dashboard.html
Обязательно: блок «требует внимания», KPI, фильтр филиала, заказы на сегодня, лента событий.

Клиенты
Референс: https://gavan-phi.vercel.app/clients.html
Обязательно: список + фильтры; модалка «Новый клиент»; панель/drawer при клике на клиента (детали).

Объекты
Референс: https://gavan-phi.vercel.app/objects.html
Обязательно: список + фильтры; карточка/детали объекта при клике.

Заявки (лиды)
Референс: https://gavan-phi.vercel.app/leads.html
Обязательно: Kanban + фильтры; создание заявки; смена колонки / причина потери.

Сделки
Референс: https://gavan-phi.vercel.app/deals.html
Обязательно: summary-карточки + Kanban + фильтры; создание / потеря / завершение сделки.

Календарь заказов
Референс: https://gavan-phi.vercel.app/orders.html
Обязательно: виды День / Неделя / Месяц / Расписание; создание заказа; drawer заказа по клику на событие.

Каркас CRM: боковое меню, верхняя панель (уведомления, пользователь/роль), область контента. Меню сворачивается.


3.3. Клинер (mobile)

Календарь клинера
Референс: https://gavan-phi.vercel.app/calendar.html
Обязательно: только свои заказы, только просмотр; виды День / Неделя / Список.

Заказ (до старта)
Референс: https://gavan-phi.vercel.app/order-work.html
Обязательно: карточка заказа; кнопка «Прибыл на место»; чек-лист заблокирован до старта; детали объекта (карта, заметки, фото).

Заказ в работе
Референс: https://gavan-phi.vercel.app/order-work.html?started=1
Обязательно: чек-лист активен (выполнено / не выполнено, комментарий, фото); «Сдать на проверку» только когда все пункты выполнены.

Нижняя навигация клинера: Заказ / Календарь / Выйти (или эквивалент).


4. Сценарии, которые должны читаться в прототипе

Менеджер: вход → дашборд → клиенты / объекты / заявки → сделки → календарь заказов.

Клинер: вход → календарь → заказ → прибыл → работа по чек-листу → сдача на проверку.

Связь экранов кликабельная (Figma prototype).


5. Компоненты (design system)

Собрать библиотеку с вариантами состояний:

1. Sidebar / Topbar / уведомления / меню пользователя
2. Button (основная, вторичная, опасная, disabled, full-width, compact)
3. Input / Select / Textarea / Field
4. Badge / статус-чип (семантика статусов заказа и чек-листа)
5. Card / KPI / «требует внимания»
6. Table + empty + pagination
7. Toolbar (поиск + фильтры)
8. Kanban: колонка + карточка
9. Calendar event (цвет/метка по статусу)
10. Drawer и Modal
11. Checklist item (свёрнут / развёрнут, фото)
12. Mobile shell + bottom nav
13. Toast / ошибка валидации

Цвета статусов — на усмотрение дизайнера, но одна и та же семантика на всех экранах:
• Заказ: Черновик → Запланирован / Назначен → В работе → На проверке → Выполнен / Отменён
• Чек-лист: Ожидает / Выполнен / Не выполнен


6. Состояния

Для ключевых экранов прорисовать:
• Default
• Loading
• Empty (с пояснением и сбросом фильтров / CTA)
• Ошибка валидации в формах
• Disabled primary + короткое пояснение «почему»


7. Адаптив

CRM менеджера
• Приоритет: desktop от 1280 px
• Корректная работа от ~768 px (сворачиваемое меню, горизонтальный scroll таблиц и kanban)

Клинер
• Portrait phone
• В финальных макетах — полноценный mobile layout, не «телефон внутри телефона»


8. Вне scope

Не проектировать в рамках этого ТЗ:
• Кабинет клиента / публичный сайт
• Экран контроля качества (QA)
• Задачи, история, сотрудники, бригады, услуги — как отдельные экраны
• Нативные iOS/Android приложения
• Сложный BI, чаты, банк, SMS/Telegram


9. Deliverables

1. Figma: Foundations (токены на выбор дизайнера) + Components + экраны из п. 3
2. Кликабельный прототип двух сценариев (п. 4)
3. Спека для разработчика: отступы, состояния, иконки (SVG)
4. Именованные слои, auto-layout


10. Критерии приёмки

• Все экраны из п. 3 покрыты; лишнего нет (или явно помечено out of scope).
• Клинерский UI очевидно проще и крупнее менеджерского.
• Модалки/drawer клиентов и заказов соответствуют поведению макетов.
• Статусы консистентны между дашбордом, календарём и карточкой заказа.
• Прототип проходит сценарии менеджера и клинера без «дыр».
